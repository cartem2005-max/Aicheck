# V4_STYLE_CRITERIA: критерий успеха v4 («переписать готовый AI-пост словами и манерой основателя») на dev

Время создания: 2026-11-25T20:50:55Z (UTC); локально Thu Nov 26 01:50:55 2026

## Идея
Не писать с нуля и ничего не выдумывать: взять готовый AI-текст и переписать его словами, оборотами, длиной и ритмом фраз автора канала (основателя). Факты, мысли и порядок те же. Как у ботов-копий людей (desk-app): реальные посты автора, ближайшие по теме к конкретному тексту + запрет копировать коронные фразы.

## Метод (фиксирую)
- **Переписывание:** `src/style_rewrite.js`, claude-sonnet-5-5 (thinking between_tools, effort low). 4 ближайших founder-поста как образец слов и манеры (пост-источник AI-текста исключён), список заезженных фраз (worn) запрещён, длина 70–110% исходной. Код: `checkFacts` (потеря/добавление → один повтор с перечнем; снова нет → статус «человеку»), `copyRate` и `worn` (флаг → повтор), длина вне диапазона → повтор. Без выбора лучшего по какой-либо оценке (против Goodhart). Для вердикта берётся итоговый текст, даже если статус «человеку».
- **Оценка «это AI»:** промпт дословно из `eval/baseline_ai.js`, claude-sonnet-5-5, effort low, **среднее трёх вызовов** на текст до и после. «До» для 20 AI считается заново (кэш v3_judge.json даёт готовое только для совпавших текстов). σ = 5,06 (`eval/results/noise_dev.md`, std одного вызова, ddof=1).
- **Слепой парный выбор «кто основатель»:** claude-haiku-5-5 (thinking отключён). Пара = переписанный текст vs НАСТОЯЩИЙ пост основателя на близкую тему: если пост-источник AI-текста — founder-пост (dev), берём его (та же новость); иначе ближайший по теме founder-пост, не входящий в 4 образца этого текста. Вопрос: «Один из двух постов написал основатель канала (живой человек), другой написан не им. Какой написал основатель: 1 или 2? Ответ: «1» или «2»». Каждая пара спрашивается в ОБЕ позиции (переписанный первым и вторым; случайна только позиция в первом вызове, зерно 4402; второй вызов — зеркало). Метрика: доля вызовов (из 40), где переписанный назван основателем.
- **Контроль слепого выбора:** 10 пар «founder-пост против другого founder-поста на близкую тему» (первый — случайные 10 из 22 founder-постов, зерно 4403, второй — ближайший по теме другой founder-пост), тот же вопрос, обе позиции (20 вызовов). Ожидаем ~50% для «первого» поста; сильное смещение от 50% = у оценщика смещение по позиции/длине, и 30% нельзя читать в лоб (оговорка в отчёте).

## Критерий успеха (на 20 AI)
1. **Падение оценки** (среднее «до» минус среднее «после» по 20 текстам, оценка текста = среднее трёх вызовов) **>= 15 пунктов И >= 2σ (то есть >= 10,1)**; фактически работает 15.
2. **Парно лучше:** «после» строго ниже «до» у **>= 15 из 20**.
3. **Слепой выбор:** переписанный назван основателем в **>= 30%** вызовов (из 40). Для контроля (founder против founder) ожидаем ~50%, пишем фактическое число.
4. **Факты:** `checkFacts(оригинал, результат).ok` у **>= 18 из 20** (итоговый текст, после повтора).
5. **Флаги:** `copyRate` (доля 4-грамм >= 3% или общая цепочка >= 6 слов) и `worn` (заезженные фразы, которых не было в оригинале) — **0 из 20**.
6. **Вердикт:** «успех» = выполнены пункты 1–5. Падение < 8 пунктов = «пишем честно и дальше не идём» (v4 не делаем). Падение 8–15 или не прошли остальные пункты = «не прошло», решение за ведущим. В бот не встраиваем в любом случае.

Editorial 10: те же числа (падение, парно, факты, флаги) для информации; на вердикт не влияют. Отдельно пишем, у скольких «после» выше «до» больше чем на σ (регрессия).

Бюджет шага: <= $1,5 по `eval/results/cost.json` (на старте 8,957773). OpenAI не используется.

## Поправка 1 (после первого платного прогона; числа и пороги выше не менялись)
- Шлюз `llm.chat` бракует ответ короче 5 знаков, поэтому ответ haiku «1» / «2» считался пустым (60 вызовов, копейки, результатов нет). Формат ответа в слепом выборе теперь «Ответ: 1» / «Ответ: 2». Вопрос и всё остальное прежнее.
- Потолок бюджета считается по записям cost.json с тегами `v4_*`, а не по общему итогу: параллельная сессия платит в тот же cost.json (за время шага +1,57 $ с тегом explain_dev), общий итог для учёта моего расхода не годится.
